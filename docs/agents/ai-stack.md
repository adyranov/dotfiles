# AI agents, sandbox and launcher

Read this before editing `home/.chezmoidata/ai/**`, `home/.chezmoitemplates/base/ai/**`, any agent config root (`claude`, `omp`, `opencode`, `pi`), nono or DCG files, AI `run_onchange` scripts, or `home/private_dot_local/exact_bin/executable_{agent,llm-*}`.

- **Toolchain Enablement**: The `ai` toolchain gates the nested `pi`, `opencode`, `omp`, and `claude` agent toolchains. Controlled in `.chezmoi.yaml.tmpl`.
- **Sandbox**: nono is the only sandbox tool. Each agent's profile (`~/.config/nono/profiles/<agent>.json`) extends its upstream signed pack (`nolabs-ai/<agent>`, pulled by a `run_onchange` script) plus built-in profiles, and adds a thin overlay rendered from `home/.chezmoidata/ai/sandbox.toml`: relocated config paths, the egress allowlist, credential routes, and env deny globs. Keep that file plain TOML (no template directives). Do not rebuild a custom base profile or policy compiler; prefer upstream pack defaults.
- **Containers & Autonomous Fleets**: Linux docker containers (`host.type == "ephemeral"`) run agents without nono; the container is the boundary. Autonomous multi-agent fleets driven by external orchestrators (Archon, Cezar, Gas City) run inside a container or on `infer01`; interactive sessions on the Macs use `nono` (no in-repo worker contract).
- **Desktop Built-in Sandbox & Plugins**: On macOS, Desktop and IDE Claude sessions run shell commands under Claude Code's built-in sandbox (`failIfUnavailable: true`, sharing `allow_domain` and `claude_builtin.deny_read` from `sandbox.toml`; `~/.config/gh/hosts.yml` stays readable because `gh` stores its token in the macOS Keychain, which remains denied); under `agent claude`, `dcg/claude-settings.json` turns it off so `nono` owns containment. Installed Claude plugins under `~/.local/share/claude` are read-only inside the sandbox (except `plugins/data`); install or update plugins only from host Claude. Manage Claude MCP servers exclusively via `home/.chezmoidata/ai/mcp.toml` (`modify_private_dot_claude.json` resets user and per-project MCPs on apply).
- **Credentials**: nono's proxy injects provider, Brave, and GitHub tokens read from the launching environment (`env://` on all OSes) and the agent sees phantoms. Claude has no route (own keychain login) and `openai-codex` uses the agent's ChatGPT OAuth file. Secrets reach `agent` only via inherited env (org-level direnv files outside repos: `~/src/.envrc`, `~/src/<org>/.envrc`); the wrapper never loads secrets. Subscription Opus lives strictly in unmodified Claude Code (Pi's Anthropic route is disabled, as are native Anthropic providers on OpenCode/OMP). `deepseek`, `openrouter`, and `opencode` route via `nono` phantoms to `omp`/`opencode`/`pi` only (never Claude). Real protection comes from scoped credentials and GitHub rulesets, not from command filtering.
- **Accepted Residuals**: subscription OAuth sessions each harness must read and refresh itself (Claude's macOS keychain login, `openai-codex` ChatGPT OAuth in pi's and OpenCode's `auth.json`, work Copilot), limited by per-agent grants so an agent can read only its own (revoke from the provider's sessions page if leaked); agent writes to working-repo files that host tools later execute (`.git` config/hooks, `.mise.toml`, `.mise/tasks/*`, `.pre-commit-config.yaml`, `.claude/settings*.json`, `.mcp.json`, and in this repo chezmoi templates, `modify_*` files, and `run_*` scripts rendered by `chezmoi diff` and `mise run lint` — always inspect with `git diff` first); the Desktop window between a planted Claude setting and the next apply; Desktop sandbox escapes approved by the auto-mode classifier rather than prompted to the owner; the broad egress allowlist; DCG as an accident guard; unsandboxed Desktop on Linux; and any future tool executing from `~/.cache`.
- **DCG & Guardrail Integrity**: destructive_command_guard is an accident guard, not a security boundary. All 4 guard scripts (`claude-guard.mjs`, `opencode-guard.js`, `pi-guard.ts`, `omp-guard.ts`), `guard-core.mjs` (both Bash command checks and `fileWriteBlockReason` write-axis floors across all 4 harnesses), and Claude's read-only override settings (`claude-settings.json`) live inside kernel-read-only `~/.config/dcg/`. The launcher injects read-only CLI flags (`claude --settings ~/.config/dcg/claude-settings.json`, `pi --extension ~/.config/dcg/pi-guard.ts`, `omp --extension=~/.config/dcg/omp-guard.ts`), OpenCode auto-discovers its symlink `~/.config/opencode/plugins/dcg-guard.js -> ~/.config/dcg/opencode-guard.js`, and the launcher's pre-launch check verifies runtime presence (`node` for Claude) and refuses to start if guards are missing or writable configs were tampered with (`disableAllHooks`, `bypassPermissions`, or replaced symlink). Approve DCG blocks in your terminal (`dcg allow <rule-id> --reason …` for built-in packs; `dcg allowlist add-command …` for custom packs under `~/.config/dcg/packs/`).
- **Denials**: a blocked path or host goes through the user as a source edit plus a user-applied update. Sandboxed agents report denials and never self-approve or self-widen; do not retry via alternate write paths (`cp`, `mv`, `sed -i`, Python writes, temp-file swaps).
- **Parity rule**: every agent (claude, omp, opencode, pi) follows the same shared contract — one config root, no named profiles (`~/.config/claude`, `~/.config/omp/agent`, `~/.config/opencode`, `~/.config/pi/agent`), one shared skills directory (`~/.config/agents/skills` from `libraries.toml`), shared MCP catalog (`mcp.toml`), shared tier routing (`models.toml`), and shared 5-role roster (`roles.toml` + `.chezmoitemplates/base/ai/roles/`). Read-only roles (`explorer`, `oracle`) have no file-edit tools, and `oracle` keeps shell access for inspection commands (tests, git, grep). New harness capabilities land in Pi only (tracked in `docs/pi-parity.md`); omp and OpenCode+Slim keep the shared contract without new features. Claude Code runs pure native Anthropic `@agents` on Pareto tiers (`claude_preset = "anthropic"` on both `personal` and `work`), while `omp`, `opencode`, and `pi` support cloud, `infer01` (personal only), and local models as providers.
- **Local LLM**: `local-llm/config.json.tmpl` selects the serving engine by platform (`omlx` on Apple Silicon, `llamacpp` elsewhere); static `llm-serve`, `llm-pull`, and `llm-bench` read it via `jq`.
- **Launcher**: `agent pi|omp|oc|claude` (`opencode` is an alias, `cc` for Claude Code) runs `nono run --profile <agent>` (a nono sandbox profile, not a config variant); `agent claude -w [name]` opts into a native worktree. Arguments after `--` pass through. The launcher uses explicit agent cases; adding an agent also touches the `.chezmoi.yaml.tmpl` agents list and icons, `base/helpers/any-agent-toolchain`, the per-agent block in `home/.chezmoiignore.tmpl`, the nono pack loop in `.mise.toml` `[tasks.update]`, `home/.chezmoidata/base/packages/<agent>.toml`, a `sandbox.toml` agent entry, and the `_agent` completion. `--no-sandbox` skips nono for debugging (DCG stays on); nested launches inherit their parent sandbox. Worktrees: `.slim/worktrees/` (OpenCode+Slim), `.claude/worktrees/` (`agent claude -w`), omp isolated tasks under `~/.local/share/omp/wt`; pi has no worktree isolation (`docs/pi-parity.md`).
- **AI tests**: `tests/ai.bats` and `tests/render.bats` check shared symlinks, DCG hooks (command + write-axis), `agent` launcher, rendered nono profiles, OAuth/parity invariants, and live nono sandboxing (live probes skip inside a sandbox or when the binary is missing).
